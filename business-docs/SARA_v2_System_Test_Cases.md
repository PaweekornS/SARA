## 1. วิธีใช้เอกสารนี้

### รูปแบบของเคส

```
### TC-M4-05 · ชื่อเคส                                    [P0] FR-M4-06 · §4.2
**ก่อนเริ่ม:** สภาพที่ระบบต้องอยู่ก่อนทำเคสนี้
**ขั้นตอน:** 1. … 2. … 3. …
**ผลที่ต้องได้:** เกณฑ์ที่ตรวจสอบได้จริง ไม่ใช่ความรู้สึก
```

### ระดับความสำคัญ

| ระดับ | ความหมาย | ถ้าไม่ผ่าน |
|---|---|---|
| **P0** | หลักการที่ห้ามละเมิด — ความถูกต้องของข้อมูลราชการ | หยุดส่งงาน แก้ก่อน |
| **P1** | ฟีเจอร์ Must ตาม requirement | ต้องแก้ก่อนใช้จริง |
| **P2** | ฟีเจอร์ Should / คุณภาพ UX | บันทึกเป็นหนี้ทางเทคนิค |
| **P3** | Could / ความสวยงาม | ทำเมื่อมีเวลา |

### ลำดับที่แนะนำให้ไล่

```
TS-ENV → Smoke → TS-M1 → TS-M3 → TS-M2 → TS-M9 → TS-M4 → TS-M5 → TS-M6 → TS-M7 → TS-M8 → TS-M10 → TS-UX → TS-NEG → TS-REG
```

เหตุผล: ต้องมีชุดการประชุมและทะเบียนบุคคลก่อน จึงจะนำเข้าการประชุมได้ · ต้องรับรองรายงานก่อน จึงจะสร้างวาระได้ · TS-NEG เป็นเคสที่ทำให้ข้อมูลเสียหาย ให้ไว้ท้ายสุด

### กติกาการรีเซ็ตระหว่างเทส

เคสที่ทำให้ข้อมูลเปลี่ยนถาวรจะมีป้าย **⟲ ต้องรีเซ็ต** กำกับ ให้รันคำสั่งนี้ก่อนไปชุดถัดไป

```bash
docker compose exec backend python -m app.seed --reset
```

## 2. การเตรียมสภาพแวดล้อม

### 2.1 สิ่งที่ต้องมีก่อน

| รายการ | จำเป็น | หมายเหตุ |
|---|---|---|
| Docker + Docker Compose | ✔ | รันทุกบริการ |
| `APP_AI4THAI_API_KEY` ที่ใช้ได้จริง | ✔ | **backend จะไม่ boot ถ้าไม่มีคีย์นี้** — `app/core/config.py` ประกาศเป็น required field และ `llm.py` สร้าง client ตอน import |
| อินเทอร์เน็ตออกไป `tokenmind.pathumma.in.th` | ✔ | ใช้ทั้ง ASR และ LLM |
| บัญชี SMTP (Gmail app password) | เฉพาะ TS-M7 | ถ้าไม่มี เคสส่งจริงจะได้ผลเป็น `failed` ซึ่งยังทดสอบเส้นทาง error ได้ |
| Microsoft Word หรือ LibreOffice | เฉพาะ TS-M5 | ตรวจไฟล์ `.docx` ที่ export ออกมา |
| เบราว์เซอร์ Chrome/Edge รุ่นล่าสุด | ✔ | |

### 2.2 ขั้นตอนติดตั้ง

```bash
# 1. เตรียมค่าตั้งต้น
cp .env.example .env
#    แก้ค่าต่อไปนี้ใน .env ให้เป็นของจริง
#    APP_AI4THAI_API_KEY=...
#    SMTP_USER=... / SMTP_PASSWORD=...
#    SECRET_KEY=<สุ่มมาใหม่ ห้ามใช้ change-me-in-production>
#    DATABASE_URL ไม่ต้องแก้ — docker-compose เขียนทับให้อยู่แล้ว

# 2. รันทุกบริการ
docker compose up -d --build

# 3. ดูว่า migrate ทำงานจบเรียบร้อย
docker compose logs migrate
#    ต้องเห็น "สร้างข้อมูลตั้งต้นเรียบร้อย"

# 4. ตรวจว่าทุกบริการขึ้นครบ
docker compose ps
```

> ⚠ ถ้าเครื่องมี PostgreSQL ของตัวเองที่พอร์ต 5432 อยู่แล้ว จะชนกัน — แก้ port mapping ใน `docker-compose.yaml` เป็น `"5433:5432"` (ภายใน compose ยังคุยกันที่ `db:5432` เหมือนเดิม)

## TS-ENV · สภาพแวดล้อมและการติดตั้ง

### TC-ENV-01 · ติดตั้งจากศูนย์ด้วย 3 คำสั่ง [P1]
**ก่อนเริ่ม:** เครื่องไม่มี container ของโปรเจกต์นี้เลย (`docker compose down -v` แล้ว)
**ขั้นตอน:**
1. `cp .env.example .env` แล้วใส่ `APP_AI4THAI_API_KEY` ของจริง
2. `docker compose up -d --build`
3. รอจน `docker compose ps` แสดงทุกบริการเป็น running/healthy
**ผลที่ต้องได้:** ทุกบริการขึ้นครบ 8 ตัว · ไม่ต้องรันคำสั่ง migration หรือ seed ด้วยมือเลย · เปิด http://localhost:3000 แล้วมีข้อมูลตั้งต้นครบ

### TC-ENV-02 · migration ถูกรันโดย service `migrate` [P1]
**ขั้นตอน:** `docker compose logs migrate`
**ผลที่ต้องได้:** เห็น log ของ alembic `Running upgrade -> 907976775cac` ตามด้วย `สร้างข้อมูลตั้งต้นเรียบร้อย` · exit code 0 · container จบการทำงาน (ไม่ restart วน)

### TC-ENV-03 · seed ไม่สร้างซ้ำเมื่อมีข้อมูลอยู่แล้ว [P1]
**ขั้นตอน:** `docker compose exec backend python -m app.seed`
**ผลที่ต้องได้:** ข้อความ `มีข้อมูลอยู่แล้ว — ใช้ --reset ถ้าต้องการล้างแล้วสร้างใหม่` · จำนวนมติยังเป็น 12 ไม่กลายเป็น 24

### TC-ENV-04 · seed ปฏิเสธการทำงานเมื่อยังไม่มีตาราง [P1]
**ก่อนเริ่ม:** ล้างฐานข้อมูล `docker compose down -v` แล้ว `docker compose up -d db redis`
**ขั้นตอน:** `docker compose run --rm backend python -m app.seed`
**ผลที่ต้องได้:** ออกด้วยข้อความ `ยังไม่มีตารางในฐานข้อมูล … รัน alembic upgrade head ก่อน` · **ต้องไม่สร้างตารางเอง** (ถ้าสร้างเอง migration ที่หายไปจะถูกกลบจนไม่มีใครรู้)

### TC-ENV-05 · รีเซ็ตข้อมูลกลับสู่สภาพตั้งต้น [P1]
**ขั้นตอน:** `docker compose exec backend python -m app.seed --reset`
**ผลที่ต้องได้:** ทุกยอดในตาราง §3.1 กลับมาตรงเป๊ะ · หน้าเว็บ refresh แล้วเห็นข้อมูลเดิม

### TC-ENV-06 · backend ไม่ boot เมื่อขาด API key [P2]
**ขั้นตอน:** ลบบรรทัด `APP_AI4THAI_API_KEY` ออกจาก `.env` แล้ว `docker compose up -d backend`
**ผลที่ต้องได้:** container ล้มพร้อม `ValidationError` ที่ระบุชื่อฟิลด์ชัดเจน — ล้มเร็วดีกว่าขึ้นมาแล้วพังตอน user กดใช้งาน
**⟲ ต้องคืนค่า `.env` กลับ**

### TC-ENV-07 · CORS อนุญาตเฉพาะ origin ที่ตั้งไว้ [P2]
**ขั้นตอน:** เรียก `GET /api/bootstrap` ด้วย header `Origin: http://evil.example.com`
**ผลที่ต้องได้:** response ไม่มี header `Access-Control-Allow-Origin` สำหรับ origin นั้น · แต่ `http://localhost:3000` ได้รับอนุญาตปกติ

### TC-ENV-08 · frontend ในคอนเทนเนอร์ต่อ backend จริง ไม่ใช่ mock [P0]
**ขั้นตอน:** เปิด http://localhost:3000 → DevTools → Network → refresh
**ผลที่ต้องได้:** เห็นคำขอไปที่ `http://localhost:8000/api/bootstrap` · เปลี่ยนสถานะมติในหน้าเว็บแล้วค่านั้นอยู่ใน PostgreSQL จริง (ตรวจด้วย `psql`) · ถ้าไม่เห็นคำขอเลย แปลว่า `NEXT_PUBLIC_USE_MOCK` ไม่ได้ถูกส่งเป็น build arg

### TC-ENV-09 · ปริมาณข้อมูลรอดข้าม restart [P1]
**ขั้นตอน:** เปลี่ยนสถานะมติสักข้อ → `docker compose restart backend db` → refresh หน้าเว็บ
**ผลที่ต้องได้:** สถานะที่เปลี่ยนยังอยู่ · ไฟล์ที่อัปโหลดไว้ก่อนหน้ายังอยู่ใน volume `shared_uploads`

### TC-M2-01 · นำเข้าไฟล์ transcript (.txt) จบครบทุกขั้น [P0] FR-M2-02, 03
**ก่อนเริ่ม:** เตรียม `meeting6.txt` ตาม §3.4 · ข้อมูลอยู่ในสภาพตั้งต้น
**ขั้นตอน:**
1. เข้าชุดบริหาร → "การประชุม" → "อัปโหลดการประชุมครั้งใหม่"

3. ครั้งที่ = 6 (ระบบควรเติมให้เอง) · วันที่ประชุม = 2026-08-20
4. กด "เริ่มประมวลผล"
**ผลที่ต้องได้:**
- เด้งไปหน้าการประชุมครั้งที่ 6 ทันที ไม่ต้องกดอะไรเพิ่ม

- แต่ละขั้นเปลี่ยนสีทีละขั้นแบบสด (poll ทุก 3 วินาที) ไม่ต้อง refresh เอง
- ขั้น "ถอดเสียง" แสดงรายละเอียด `ได้ 11 ท่อน` (จำนวนบรรทัดในไฟล์)
- ขั้น "แยกผู้พูด" แสดง `ASR ไม่คืนข้อมูลผู้พูด — ให้ระบุผู้พูดเองในหน้าตรวจทาน` (ไฟล์ .txt ไม่มี speaker label)
- จบแล้วสถานะการประชุมเป็น `draft` และหน้าเปลี่ยนไปแสดงแท็บตรวจทาน

### TC-M2-02 · นำเข้าไฟล์เสียงจริง [P1] FR-M2-01, 06
**ขั้นตอน:** อัปโหลด `sample.m4a` เป็นการประชุมครั้งที่ 7
**ผลที่ต้องได้:** ขั้นถอดเสียงเรียก AI4Thai จริง (เห็นใน log ของ worker) · ได้ท่อนบันทึกพร้อม `start_ms`/`end_ms` จริง · ถ้า ASR คืน speaker label มาด้วย ขั้นแยกผู้พูดจะแสดง `แยกได้ N ผู้พูดจากผลของ ASR`
**เวลาที่ควรใช้:** ไฟล์ 5 นาที ควรเสร็จภายใน 3 นาที

### TC-M2-03 · **ASR ล้มเหลว = หยุด pipeline ไม่แต่งข้อมูล** [P0] FR-M2-04 ⭐
**นี่คือเคสสำคัญที่สุดในเอกสารนี้** — v1 เคยใส่ transcript ปลอมเมื่อ ASR พัง
**ขั้นตอน:**
1. อัปโหลดไฟล์ใด ๆ เป็นครั้งที่ 8
2. **ติ๊กสวิตช์ "จำลองสถานการณ์ ASR ล้มเหลว"**
3. กด "เริ่มประมวลผล" แล้วรอ
**ผลที่ต้องได้:**
- ขั้น "รับไฟล์" ✔ เขียว
- ขั้น "ถอดเสียง" ✖ แดง พร้อมข้อความ `โหมดจำลอง: ASR API ไม่ตอบสนอง (HTTP 504 หลัง retry 3 ครั้ง) — หยุด pipeline ไม่มีการสร้าง transcript ทดแทน`
- ขั้น "แยกผู้พูด" / "สกัดมติ" / "พร้อมตรวจทาน" ยังเป็นสีเทา **ไม่เดินต่อ**
- สถานะการประชุม = `failed`

### TC-M4-05 · **ระบบปิดมติเองไม่ได้** [P0] FR-M4-06 · §4.2 ⭐⭐
**นี่คือหลักการที่ห้ามละเมิดที่สุด**
**ขั้นตอน:**
1. ประมวลผลครั้งที่ 6 เสร็จ แต่ **ยังไม่กดยอมรับข้อเสนออะไรเลย**
2. `GET /api/resolutions/{id_ของ_มติ_5/2569_ข้อ_4.3}`
**ผลที่ต้องได้:**
- สถานะยังเป็น `in_progress` **ไม่ใช่** `done` แม้ระบบจะเสนอปิดแล้วก็ตาม
- ในหน้าจอ ปุ่มบนข้อเสนอนั้นเขียนว่า **"ยืนยันปิดมติ"** ไม่ใช่ "ยอมรับ" และมีข้อความกำกับ *"ระบบเสนอเท่านั้น — มติจะปิดก็ต่อเมื่อท่านกดปุ่มนี้"*
- หลังกดปุ่มแล้วเท่านั้น สถานะจึงเปลี่ยนเป็น `done`
- **ทดสอบระดับ API:** ไม่มี endpoint ใดที่ทำให้มติเป็น `done` ได้โดยไม่ผ่าน action ของผู้ใช้ — เรียก `POST /api/meetings/{id}/approve` แล้วมติที่ระบบเสนอปิดต้อง**ไม่**ถูกปิด

### TC-M4-06 · ระบบเปลี่ยน proposed → confirmed ได้ที่เดียวเท่านั้น [P0] §4.1
**ขั้นตอน:** ยอมรับข้อเสนอมติใหม่ → ตรวจสถานะ → กด "รับรองรายงาน" → ตรวจสถานะอีกครั้ง
**ผลที่ต้องได้:** หลังยอมรับข้อเสนอ มติใหม่มีสถานะ `proposed` · หลังรับรองรายงานเท่านั้นจึงเปลี่ยนเป็น `confirmed` · ประวัติการแก้ไขบันทึกเหตุผล `ที่ประชุมรับรองรายงานการประชุม`

### TC-M4-07 · state machine ปฏิเสธการข้ามขั้น [P0] FR-M4-03 · §4.1
**ขั้นตอน:** `POST /api/resolutions/{id}/status` โดย id เป็นมติสถานะ `superseded` ส่ง `{"status":"in_progress","reason":"ทดสอบ"}`
**ผลที่ต้องได้:** HTTP **409** `เปลี่ยนสถานะจาก superseded ไป in_progress ไม่ได้ตาม state machine`
**ตารางที่ต้องบังคับใช้:**

| จาก | ไปได้ |
|---|---|
| `proposed` | `confirmed` · `cancelled` |
| `confirmed` | `in_progress` · `blocked` · `done` · `cancelled` · `superseded` |
| `in_progress` | `blocked` · `done` · `cancelled` |
| `blocked` | `in_progress` · `done` · `cancelled` |
| `done` | `in_progress` (เปิดใหม่) |
| `cancelled` | `confirmed` |
| `superseded` | **ไม่ได้เลย** |

### TC-M4-08 · ตรวจ state machine ครบทุกช่อง [P1] FR-M4-03

### TC-M7-11 · **scheduler สร้างรายการเตือนเข้าคิวรออนุมัติ** [P1] FR-M7-06 ⭐
**ขั้นตอน:**
```bash
docker compose exec celery_worker python -c "from app.workers.tasks import scan_due_resolutions; print(scan_due_resolutions())"
```
**ผลที่ต้องได้:**
- คืน `{"queued": N}` โดย N > 0
- รายการที่สร้างมีสถานะ **`pending_approval`** ทุกรายการ — scheduler สร้างได้ แต่ส่งเองไม่ได้
- หัวเรื่องแยกสองแบบ: เกินกำหนดแล้ว → `แจ้งเตือน: มติ X เกินกำหนดแล้ว N วัน` · ยังไม่ครบ → `แจ้งเตือน: มติ X ครบกำหนดวันที่ ๓๑ สิงหาคม ๒๕๖๙`
- ครอบคลุมมติที่ครบกำหนดภายใน `REMINDER_LEAD_DAYS` (7 วัน) เท่านั้น

### TC-M7-12 · scheduler ไม่สแปมคนเดิมเรื่องเดิม [P1]

**ผลที่ต้องได้:** ตอบว่า **"ไม่พบข้อมูลที่เกี่ยวข้องในชุดการประชุมนี้ ระบบจะไม่คาดเดาคำตอบเมื่อไม่มีหลักฐานอ้างอิง"** · ไม่มีการอ้างอิงปลอม · **ห้ามแต่งคำตอบขึ้นมา**

### TC-M8-07 · ค้นภาษาไทยที่ไม่มีช่องว่างระหว่างคำ [P1]
**ขั้นตอน:** ถาม `ครุภัณฑ์คอมพิวเตอร์` (คำติดกัน ไม่มีเว้นวรรค)
**ผลที่ต้องได้:** พบมติ 5/2569 ข้อ 4.1 — ระบบใช้ n-gram ระดับตัวอักษร ไม่ใช่การตัดด้วยช่องว่างซึ่งจะพลาดทุกครั้งกับภาษาไทย

### TC-M8-08 · ตอบได้แม้ LLM ล่ม [P1]
**ขั้นตอน:** ตั้ง `PATHUMMA_MODEL_NAME` เป็นชื่อโมเดลที่ไม่มีจริง → restart → ถามคำถาม
**ผลที่ต้องได้:** **ยังได้คำตอบ** ที่ประกอบจากข้อเท็จจริงที่ค้นเจอ (มติ · สถานะ · กำหนด · ไทม์ไลน์) พร้อมการอ้างอิงครบ · การเรียบเรียงหยาบกว่าเดิมแต่ข้อมูลถูกต้อง — **การอ้างอิงมาจากขั้นค้นหา ไม่ได้มาจากโมเดล จึงอ้างมั่วไม่ได้**
**⟲ ต้องคืนค่า `.env`**

### TC-M8-09 · คำถามว่างถูกปฏิเสธ [P2]
**ขั้นตอน:** `POST /api/series/{id}/ask` ด้วย `{"question":"   "}`
**ผลที่ต้องได้:** HTTP **422** `กรุณาระบุคำถาม`

### TC-M8-10 · ประวัติคำถามถูกเก็บและแสดงได้ [P2]
**ขั้นตอน:** ถาม 3 คำถาม → refresh หน้า
**ผลที่ต้องได้:** ทั้ง 3 คำถามและคำตอบยังอยู่ เรียงตามเวลา · ปุ่ม "ล้างประวัติคำถาม" ลบได้

### TC-M8-11 · คำถามตัวอย่างช่วยเริ่มต้น [P2]
**ขั้นตอน:** เปิดหน้าถาม-ตอบครั้งแรก
**ผลที่ต้องได้:** มีคำถามตัวอย่างให้กดเลย ไม่ต้องนึกเอง — คลิกแล้วถามทันที

### TC-M8-12 · ถามข้ามชุดไม่ปนกัน [P1]
**ขั้นตอน:** ถามคำถามเดียวกันในชุด "คณะกรรมการวิชาการ"
**ผลที่ต้องได้:** ตอบว่าไม่พบข้อมูล — ไม่ดึงมติของชุดบริหารมาตอบ

## TS-M10 · ความปลอดภัยและ audit

### TC-M10-01 · บันทึกการใช้งานเก็บทุกการกระทำสำคัญ [P1] FR-M10-05
**ขั้นตอน:** ทำการกระทำต่อไปนี้ทีละอย่าง แล้วดูหน้า "บันทึกการใช้งาน"
**ผลที่ต้องได้:** ทุกอย่างต่อไปนี้ต้องมีบันทึก พร้อม ผู้กระทำ · เวลา · สิ่งที่ถูกกระทำ

| การกระทำ | action ที่ต้องบันทึก |
|---|---|
| อัปโหลดการประชุม | `upload_meeting` |

| ยืนยัน alias | `confirm_alias` |
| สร้าง/ลบชุดการประชุม | `create_series` / `delete_series` |

| อนุมัติ/ยกเลิกการส่งออก | `approve_outbound_action` / `cancel_outbound_action` |

### TC-M10-02 · บันทึกภาษาไทยไม่เพี้ยน [P1]
**ผลที่ต้องได้:** ทุกแถวแสดงชื่อผู้กระทำและรายละเอียดเป็นภาษาไทยอ่านออก ไม่มี `?` หรือ mojibake

### TC-M10-03 · **ยังไม่มีระบบล็อกอิน — ต้องรู้ตัว** [P1] FR-M10-01, 02
**ขั้นตอน:** เรียก `GET /api/bootstrap` โดยไม่ใส่ header ใด ๆ
**ผลที่ต้องได้:** ได้ข้อมูลทั้งหมด HTTP 200 · header `X-Actor` ปลอมได้อิสระ
**นี่คือพฤติกรรมที่ตั้งใจของ v2 hackathon** ตามที่ระบุใน README — บันทึกเป็นความเสี่ยงที่ต้องปิดก่อนใช้งานจริง ไม่ใช่ bug ที่ค้นพบใหม่

### TC-M10-04 · SECRET_KEY เริ่มต้นต้องถูกเปลี่ยน [P0]
**ขั้นตอน:** ตรวจ `.env` ที่ใช้จริง
**ผลที่ต้องได้:** `SECRET_KEY` **ไม่ใช่** `change-me-in-production` — ถ้ายังเป็นค่าเดิม ใครก็ปลอม magic link ได้

### TC-M10-05 · ไฟล์เสียงเก็บใน volume ไม่ใช่ temp folder [P2] FR-M10-06
**ขั้นตอน:** `docker compose exec backend ls /data/uploads`
**ผลที่ต้องได้:** เห็นไฟล์ที่อัปโหลดไว้ · ไฟล์รอด `docker compose restart backend`
**หมายเหตุ:** ยังไม่ใช่ object storage (MinIO/S3) ตามที่ FR-M10-06 กำหนด — ดู §19

### TC-M10-06 · ไม่มี data isolation ระหว่างองค์กร [P2] FR-M10-03
**ขั้นตอน:** ตรวจว่า `GET /api/bootstrap` ใช้ organization ใด
**ผลที่ต้องได้:** ปัจจุบันมีองค์กรเดียวและ endpoint หยิบองค์กรแรกที่เจอ — บันทึกเป็นข้อจำกัด ไม่ใช่ผ่าน/ไม่ผ่าน

## TS-UX · ประสบการณ์ใช้งานข้ามหน้า

### TC-UX-01 · เข้าถึงงานหลักได้ใน ≤ 3 คลิก [P1]
**ขั้นตอน:** จากหน้าแรก นับจำนวนคลิกไปยังงานต่อไปนี้
**ผลที่ต้องได้:**

| งาน | คลิกสูงสุด |
|---|---|
| ดูมติที่เกินกำหนดมากที่สุด | 2 (เลือกชุด → แดชบอร์ด) |
| อัปโหลดการประชุมใหม่ | 3 (เลือกชุด → การประชุม → อัปโหลด) |
| สร้างร่างวาระ | 3 |
| อนุมัติอีเมลที่รอส่ง | 2 |
| ถามคำถามข้ามการประชุม | 3 |

### TC-UX-02 · สลับชุดการประชุมโดยไม่หลุดหน้า [P2]
**ขั้นตอน:** อยู่หน้า "ทะเบียนมติ" ของชุด A → สลับไปชุด B จากเมนูซ้าย
**ผลที่ต้องได้:** ยังอยู่ที่หน้า "ทะเบียนมติ" แต่เป็นข้อมูลของชุด B

### TC-UX-03 · ป้ายจำนวนงานค้างในเมนู [P2]
**ผลที่ต้องได้:** เมนู "คิวส่งออก" มีป้ายตัวเลขจำนวนรายการรออนุมัติ · ตัวเลขลดลงทันทีเมื่ออนุมัติ

### TC-UX-04 · สลับภาษาไทย ↔ อังกฤษ [P2]
**ขั้นตอน:** กดปุ่มสลับภาษาแล้วเดินดูทุกหน้า
**ผลที่ต้องได้:** ป้ายกำกับ UI เปลี่ยนเป็นอังกฤษ · **เนื้อหาเอกสารราชการ (ข้อความมติ · วาระ · บทประชุม) ยังคงเป็นภาษาไทยเสมอ** — ไม่แปลเอกสารทางการ

### TC-UX-05 · สลับธีมสว่าง/มืด [P2]
**ขั้นตอน:** กดปุ่มสลับธีม
**ผลที่ต้องได้:** สลับทันทีไม่กระพริบขาว (มี inline script ก่อน paint) · ค่าที่เลือกอยู่รอดหลัง refresh · **ทุกสีสถานะยังแยกออกจากกันในโหมดมืด** (ตรวจ StatusPill ทั้ง 7 สถานะ)

### TC-UX-06 · แถบแจ้งเตือนเมื่อเชื่อมต่อ backend ไม่ได้ [P1]
**ขั้นตอน:** `docker compose stop backend` → ทำอะไรสักอย่างในหน้าเว็บ
**ผลที่ต้องได้:** แถบแจ้งเตือนขึ้นบอกว่าเชื่อมต่อไม่ได้ พร้อมปุ่ม "ลองใหม่" · **ไม่ใช่หน้าขาวหรือเงียบหาย** · เปิด backend กลับมา กด "ลองใหม่" แล้วข้อมูลกลับมาปกติ

### TC-UX-07 · ข้อมูลกลับสู่สภาพจริงเมื่อคำสั่งล้มเหลว [P1]
**ขั้นตอน:** ปิด backend → เปลี่ยนสถานะมติในหน้าจอ
**ผลที่ต้องได้:** หน้าจอ**ไม่**ค้างอยู่กับค่าที่ล้มเหลว — ระบบดึงข้อมูลจริงกลับมาแสดงพร้อมข้อความ error

### TC-UX-08 · ทุกการกระทำที่กู้คืนไม่ได้ต้องมีการยืนยัน [P1]
**ผลที่ต้องได้:** modal ยืนยันปรากฏก่อน — ลบชุดการประชุม · ลบบุคคล · รับรองรายงาน · อนุมัติส่งอีเมล · เปลี่ยนสถานะเป็น done/cancelled

### TC-UX-09 · สถานะว่างมีคำแนะนำว่าให้ทำอะไรต่อ [P2]
**ขั้นตอน:** เปิดชุดใหม่ที่ยังไม่มีข้อมูล ดูทุกหน้า
**ผลที่ต้องได้:** ทุกหน้าที่ว่างมีข้อความอธิบาย + ปุ่มพาไปทำขั้นถัดไป — ไม่มีตารางเปล่าที่ไม่บอกอะไร

### TC-UX-10 · ตัวเลขทั้งหมดใช้ตัวเลขความกว้างคงที่ [P3]
**ผลที่ต้องได้:** ตัวเลขในการ์ดสถิติและตารางไม่ขยับซ้าย-ขวาเวลาค่าเปลี่ยน (`tnum`)

### TC-UX-11 · UI ไม่ลายตา [P2]
**ผลที่ต้องได้:** แต่ละหน้ามีสีเน้นไม่เกิน 2–3 สี · สีสถานะใช้ความหมายเดียวกันทุกหน้า · ไม่มีป้าย/badge ซ้อนกันจนอ่านไม่ออก · ตัวหนาใช้เฉพาะสิ่งที่ต้องอ่านก่อน

### TC-UX-12 · แสดงผลบนหน้าจอ 1366×768 [P2]
**ขั้นตอน:** ย่อหน้าต่างเป็น 1366×768 (จอโน้ตบุ๊กราชการทั่วไป)
**ผลที่ต้องได้:** ไม่มี horizontal scroll · การ์ดสถิติยังอยู่ในแถวเดียว · ตารางมติอ่านได้ครบ

### TC-UX-13 · แสดงผลบนแท็บเล็ต 768 px [P2]
**ผลที่ต้องได้:** เมนูซ้ายยุบหรือปรับตัว · การ์ดจัดใหม่เป็นคอลัมน์เดียว · ไม่มีเนื้อหาถูกตัดหาย

### TC-UX-14 · ใช้งานด้วยคีย์บอร์ดอย่างเดียวได้ [P2]
**ขั้นตอน:** กด Tab ไล่ทั้งหน้า
**ผลที่ต้องได้:** ทุกปุ่ม/ลิงก์/ช่องกรอกเข้าถึงได้ · มีกรอบ focus ที่เห็นชัด · modal ที่เปิดอยู่จับ focus ไว้ข้างใน · Esc ปิด modal ได้
**หมายเหตุ:** ยังไม่เคยตรวจ — ดู §19

### TC-UX-15 · ความคมชัดของสีตามเกณฑ์ WCAG AA [P2]
**ขั้นตอน:** ใช้ DevTools ตรวจ contrast ratio ของข้อความหลัก
**ผลที่ต้องได้:** ข้อความปกติ ≥ 4.5:1 · ข้อความใหญ่ ≥ 3:1 · ทั้งโหมดสว่างและมืด

### TC-UX-16 · ไม่มี error ใน console [P1]
**ขั้นตอน:** เดินครบทุกหน้าโดยเปิด DevTools Console ไว้
**ผลที่ต้องได้:** ไม่มี error สีแดง · ไม่มี React key warning · ไม่มี hydration mismatch

### TC-UX-17 · เวลาโหลดหน้าแรก [P2]
**ผลที่ต้องได้:** จากกด Enter ถึงเห็นข้อมูลจริง ≤ 3 วินาทีบน localhost

## TS-NEG · กรณีผิดปกติและความทนทาน

### TC-NEG-01 · id ที่ไม่มีอยู่จริง [P1]
**ขั้นตอน:** `GET /api/resolutions/00000000-0000-0000-0000-000000000000`
**ผลที่ต้องได้:** HTTP **404** พร้อมข้อความไทย `ไม่พบมติ` — ไม่ใช่ 500

### TC-NEG-02 · UUID รูปแบบผิด [P2]
**ขั้นตอน:** `GET /api/resolutions/not-a-uuid`
**ผลที่ต้องได้:** HTTP **422** จาก validation ของ FastAPI ไม่ใช่ 500

### TC-NEG-03 · หน้าเว็บของ id ที่ไม่มี [P2]
**ขั้นตอน:** เปิด `/series/<uuid ที่ไม่มีจริง>`
**ผลที่ต้องได้:** แสดง "ไม่พบชุดการประชุมนี้" ในหน้าปกติ ไม่ใช่หน้าขาวหรือ error boundary

### TC-NEG-04 · ข้อความมติยาวมาก [P2]
**ขั้นตอน:** แก้ข้อความมติเป็นข้อความยาว 2,000 ตัวอักษร
**ผลที่ต้องได้:** บันทึกได้ · แสดงในหน้าจอโดยตัดด้วย CSS · **export .docx ออกมาเต็ม** ไม่ถูกตัด

### TC-NEG-05 · อักขระพิเศษและ HTML ในข้อความมติ [P0]
**ขั้นตอน:** ใส่ข้อความมติเป็น `<script>alert(1)</script> & "คำพูด" 'ฯลฯ' <b>ตัวหนา</b>`
**ผลที่ต้องได้:**
- หน้าเว็บแสดงเป็นข้อความธรรมดา **ไม่มี alert เด้ง**
- หน้า magic link แสดงเป็นข้อความธรรมดา (ตรวจโดยดู view-source ว่ามีการ escape)
- ไฟล์ `.docx` มีข้อความตามที่พิมพ์
**⟲ ต้องรีเซ็ต**

### TC-NEG-06 · เว้นวรรคและบรรทัดใหม่ในข้อความ [P2]
**ขั้นตอน:** ใส่ข้อความมติที่มีบรรทัดใหม่หลายบรรทัด
**ผลที่ต้องได้:** แสดงและ export โดยรักษาบรรทัดใหม่ ไม่ยุบเป็นบรรทัดเดียว

### TC-NEG-07 · กดปุ่มรัว ๆ ไม่สร้างข้อมูลซ้ำ [P1]
**ขั้นตอน:** กด "สร้างร่างระเบียบวาระ" 5 ครั้งติดกันเร็ว ๆ
**ผลที่ต้องได้:** ได้ร่างเดียว ไม่ใช่ 5 ร่าง

### TC-NEG-08 · สองแท็บทำงานพร้อมกัน [P2]
**ขั้นตอน:** เปิดมติเดียวกันในสองแท็บ → เปลี่ยนสถานะในแท็บ A → กระทำต่อในแท็บ B
**ผลที่ต้องได้:** แท็บ B ได้ HTTP 409 จาก state machine หรือดึงข้อมูลใหม่มาแสดง · **ไม่เขียนทับกันเงียบ ๆ**

### TC-NEG-09 · redis ล่ม [P1]
**ขั้นตอน:** `docker compose stop redis` → อัปโหลดไฟล์
**ผลที่ต้องได้:** ระบบแจ้ง error ที่อ่านรู้เรื่อง · ไม่ตั้งสถานะการประชุมเป็นสำเร็จทั้งที่ไม่ได้ประมวลผล

### TC-NEG-10 · worker ล่มกลาง pipeline [P1]
**ขั้นตอน:** อัปโหลดไฟล์ → `docker compose kill celery_worker` ระหว่าง pipeline ทำงาน
**ผลที่ต้องได้:** สถานะการประชุมค้างที่ขั้นที่กำลังทำ (ไม่กระโดดไป done) · เปิด worker กลับมาแล้วกด "ลองใหม่" ทำงานต่อได้ · **ไม่มี transcript หรือมติที่ไม่ได้มาจากไฟล์จริงถูกสร้าง**

### TC-NEG-11 · ฐานข้อมูลล่มระหว่างใช้งาน [P2]
**ขั้นตอน:** `docker compose stop db` → ทำอะไรสักอย่าง
**ผลที่ต้องได้:** ขึ้นแถบ error · เปิด db กลับมาแล้วกด "ลองใหม่" ทำงานต่อได้ทันทีโดยไม่ต้อง restart frontend

### TC-NEG-12 · AI4Thai API ตอบช้าเกินเวลา [P2]
**ขั้นตอน:** ตั้ง `LLM_TIMEOUT_SECONDS=1` → restart → อัปโหลดไฟล์
**ผลที่ต้องได้:** pipeline ล้มที่ขั้น "สกัดมติ" พร้อม error ที่ระบุสาเหตุ · **ไม่มีมติปลอมถูกสร้าง**

### TC-NEG-13 · LLM ตอบ JSON ที่ผิดรูปแบบ [P2]

### TC-NEG-14 · วันครบกำหนดในอดีตไกลมาก [P3]
